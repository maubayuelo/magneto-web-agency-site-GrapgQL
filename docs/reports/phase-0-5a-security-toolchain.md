## Blocker — `next build` fails (regression vs Phase 0)
Next 15.5 generates `.next/types/validator.ts`, which type-checks **every file under
`src/pages/api/`** against `ApiRouteConfig`. `next build` runs that check ("Checking validity of
types …"), and so does `npm run typecheck` whenever `.next/types/` exists (after a build, dev or
typegen). Two pre-existing Known-debt items fail it:

```
.next/types/validator.ts(159,31): error TS2344: Type 'typeof import(".../src/pages/api/__tests__/contact.test")'
  does not satisfy the constraint 'ApiRouteConfig'. Property 'default' is missing …
.next/types/validator.ts(203,39): error TS2306: File '.../src/pages/api/ping-cms.ts' is not a module.
```
`npm run build` → `Failed to compile. Type error: … contact.test …` → `Next.js build worker exited with code: 1`.

Both causes are already in Known debt ("`contact.test.ts` is built and served as a public API route",
"`ping-cms.ts` is empty (0 bytes)"). Next 15.4.8 didn't validate `pages/api`, so the baseline build passed.

**Options (decision needed: Mauricio + Senior Architect):**
1. **Recommended:** a small follow-up spec (or an amendment to this one) that allows two `src/` changes:
   move `src/pages/api/__tests__/contact.test.ts` out of `pages/` (e.g. `src/__tests__/api/contact.test.ts`,
   with its import path adjusted; Vitest still finds it), and either delete `ping-cms.ts` or give it a real
   default-export handler. That resolves two Known-debt items and unblocks the build. `/api/ping-cms` would
   become 404 (delete) or 200 (handler) instead of 500, so the HTTP smoke baseline changes.
2. Set `typescript.ignoreBuildErrors: true` in `next.config.ts`. **Not recommended:** it hides every
   type error in builds, the same trap as `eslint.ignoreDuringBuilds`.
3. Stay on `next@15.4.8`. **Not recommended:** that leaves 3 critical RCE advisories open.
